# B-021 stepEnemy Ctx / `as StepCtx` cast duplicates GameState refuge optionality

Found during: T-033
Risk: low
Evidence: src/game/enemies.ts:37 — `type Ctx = GameState & { refuge?: Refuge }`; the refuge property type collapses to bare `Refuge` (required, non-null) because `(Refuge | null) & (Refuge | undefined)` reduces to `Refuge` — verified with a tsc probe, which reported `Type 'Refuge' is not assignable to...`. But at runtime the value is `Refuge | undefined`: src/game/tick.ts:50-52 `toStepCtx` maps `refuge: s.refuge ?? undefined` and forces it through with `as StepCtx` (tick.ts:48 aliases `Parameters<typeof stepEnemy>[1]`). So the type says "refuge is always a non-null object" while the runtime value is usually `undefined`, and the `state.refuge !== undefined` guard in src/game/enemies.ts:51-53 is load-bearing at runtime but dead code as far as the type system is aware. The cast papers over a null/undefined bridge the way B-011's SpawnState papered over field duplication.
Direction: make the optionality explicit and drop both locals — e.g. `stepEnemy` (and its helpers) take `GameState` directly and `isRefuge` checks `state.refuge !== null`, mirroring how spawn.ts handles `state.refuge` after T-033; then delete `Ctx` (enemies.ts:37), the `as StepCtx` cast, and `toStepCtx` (tick.ts:48-52) — or if the ctx should keep the resolved playerPos per B-018, use `Omit<GameState, "refuge"> & { refuge: Refuge | null }`. Note the related but distinct B-018 (stale player position in the same ctx) should land first or together, since both touch `toStepCtx`.
