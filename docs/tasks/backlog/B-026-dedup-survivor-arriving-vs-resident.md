# B-026 Dedup survivor keeps first-in-array; spec says the arriving one removes the resident

Found during: T-039
Risk: low
Evidence: PRODUCT_SPEC.md:237 — "If two enemies would occupy one cell, the arriving one removes the resident." vs src/game/tick.ts:142-151 — the dedup loop keeps the **first occurrence in `state.enemies` array order** and drops the rest. When a stationary enemy (`stepTimer > 0`, never re-positioned this tick) shares a cell with an enemy that stepped onto it, the survivor is whichever is earlier in the array — so the resident can survive and the arriving one can be dropped, the inverse of the spec. When two movers land on a cell neither occupied, there is no "resident" at all and the spec's phrasing does not map to array order either. The T-039 candidate correctly did not change the survivor (out of scope per its contract); the pre-existing test at test/tick.test.ts:234 only asserts that exactly one enemy remains, so it cannot distinguish the two semantics.
Direction: pick the survivor rule and pin it — e.g. on a collision, drop the mover(s) that stepped onto the cell and keep the one already resident there (if two movers share a cell, either survivor is defensible, so the spec should say which); then update the dedup in tick.ts and strengthen test/tick.test.ts:234 to assert **which** id survives. Alternatively waive the spec sentence as cosmetic (enemy kinds are the dominant visual difference, ids are not player-visible) — that is a spec decision, not a code one.
